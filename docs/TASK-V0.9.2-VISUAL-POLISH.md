## B. 播放队列动效

**根因**：队列原本没有任何过渡动画。宽屏时打开队列会改变内容区的网格列宽，整页突然重排。关闭时组件被卸载，滚动位置丢失。

**现在的做法**：

- **覆盖式抽屉**：位于顶栏与播放栏之间，不遮挡播放控制。打开时页面宽度不变（实测主内容区 1050px 和 870px 都保持不变）。
  - 正在播放页在宽屏时仍给队列让出位置，保证歌词完整可读。窗口宽度不足 1200px 时，覆盖在页面上并显示轻遮罩。
- **参数**：

| 参数 | 值 |
| --- | --- |
| 打开 | 240ms，`cubic-bezier(.16,1,.3,1)`（快速响应，末段自然减速） |
| 关闭 | 180ms，`cubic-bezier(.4,0,1,1)`（加速退出） |
| 位移 | 从右侧 40px 处滑入，同时淡入 |
| 动画属性 | 只用 `transform` 和 `opacity`；没有回弹，没有缩放 |

- **状态处理**：
  - 首次打开时挂载，之后一直保留，因此不会重复挂载，也不会重新请求队列，滚动位置得以保持。
  - 关闭后队列不再随播放器的每次轮询重新渲染。
  - 关闭时立即设置 `inert`，焦点回到队列按钮。`visibility:hidden` 延迟到关闭动画结束后才生效。
  - 首次打开借助 `@starting-style` 也有入场动画。
  - 快速连续点击时，CSS 过渡会从当前位置直接反向，不需要 `setTimeout` 或 JS 动画状态。
- **统一关闭**：Esc、关闭按钮和遮罩都走 `toggleQueue(false)`。
- **减少动态效果**：应用内开关和系统 `prefers-reduced-motion` 都会把位移设为 0，并跳过过渡动画。

## C. 音量

- **显示**：音量图标、滑块和百分比依次排列，例如“35%”。百分比使用次级文字色和等宽数字，宽度固定为 4 个字符，数字变化时不左右跳动。
  - 窗口宽度不超过 999px 时隐藏滑块和数字，数值改由按钮标签和提示显示（例如“静音（当前音量 35%）”）。
- **数值来源**：Rust 的音量是 0.0–1.0 的增益，界面只把同一个数值换算成整数百分比（`toPercent` 和 `toGain`），没有新的音量曲线。
  - 拖动时数字立即跟随草稿值。Rust 确认最后一次设置后，草稿被丢弃，界面回到 Rust 快照中的真实值。
- **IPC**：`utils/volume.ts` 的 `latest()` 保证同一时间最多只有一个请求在途，中间值会被丢弃，最后一个值一定会发送。
  - 实测 21 次拖动只产生 5 次 IPC，最终值 35% 与后端一致。
  - 请求失败时会报错，并回到真实状态。
- **独立于其他播放命令**：音量不再经过播放命令的全局锁 `control()`，其他命令进行中时滑块也不会被禁用。
- **键盘与无障碍**：原生 range 输入支持左右方向键（每次 1%）和 Home/End。读屏软件会读出 `aria-valuetext`，例如“35%”或“0%，已静音”。
- **静音**：点击喇叭切换。静音前的音量保存在内存和 localStorage（`music-mine-unmute-volume`）中，取消静音时恢复。音量本身的持久化仍由 Rust 会话负责，没有变化。
- **不触发重新渲染**：封面请求只跟随 `track_id`。实测调节音量期间封面请求为 0 次；切换主题后音量保持 35%。
- **滑块外观**：细线轨道，已设置部分用品牌色，拖动时圆点放大到 1.25 倍；圆点阴影按主题取值（`--shadow-thumb`）。

浏览器测试环境（模拟 IPC）的实测：

- 队列：在 1280×800、1100×700 和 1920 宽下实测打开、关闭和快速连续点击，结果见上文 B 节。
- 正在播放页：队列紧贴顶部，下边缘与播放栏对齐，歌词区刚好在队列左侧结束；按一次 Esc 只关闭队列。
- 窄窗口：点击遮罩只关闭队列。
- 音量：拖动、静音和取消静音的结果见上文 C 节。

测试环境的标签页有时会暂停渲染帧，导致个别动画中途的采样不准确。最终状态以设置稳定后的测量为准。
